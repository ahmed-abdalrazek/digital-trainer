# خطة مهام Codex

## المرحلة 0 — حماية وفهم
- افحص بنية المستودع و`git status` والفروع والتغييرات غير المحفوظة.
- لا تحذف أو تستبدل أي ملف قبل فهمه.
- اقرأ README والإعدادات والوثائق المتاحة وحدد التقنية والإصدارات وأوامر التشغيل.
- أنشئ `docs/PROJECT_AUDIT.md` يلخص البنية وما يعمل والفجوات والمخاطر والأسئلة.
- لا تدّعِ تشغيل اختبارات إلا إذا شغلتها فعليًا.
- اذكر بوضوح إذا كان تصدير Base44 أو وثائق مرجعية غير متاح.

## المرحلة 1 — مقارنة المتطلبات
- قارن التطبيق بـ PRD وPROJECT_CONTEXT.
- أنشئ جدول تتبع: ID، المتطلب، الحالة، موضع الكود، الاختبار، الفجوة.
- استخدم التقنية الحالية ما لم يوجد سبب واضح وموثق للتغيير.

## المرحلة 2 — Demo
- نفّذ Demo داخل التقنية الحالية إن أمكن، أو HTML مستقلًا إن كان أنسب.
- نفّذ كل الصفحات في DESIGN_SPEC.
- اجعل التنقل والبحث والفلاتر والنوافذ والتعديلات التجريبية تعمل.
- استخدم بيانات وهمية متسقة وأظهر تنبيه Demo دائمًا.
- لا تكتفِ بصورة ثابتة أو Dashboard فقط.
- اختبر Desktop وMobile وصحح overflow واتجاهات RTL.

## المرحلة 3 — اختبار وتوثيق
- شغّل اختبارات/build/lint المتاحة فعليًا وأصلح ما تسببه تغييراتك.
- تحقق من كل زر ورابط.
- حدّث README وأضف `docs/DEMO_LIMITATIONS.md`.

## المرحلة 4 — تجهيز المنتج
- بعد التدقيق، قسم الفجوات إلى مهام backend/frontend/data/security.
- لا تستخدم بيانات حقيقية أو خدمات مدفوعة دون تفويض.
- خطط لقاعدة البيانات والعزل التنظيمي.
- فرض الصلاحيات على الخادم لكل API ومسار.
- اختبر منع الوصول بتغيير معرفات المنشأة والقسم والشعبة.
- أضف audit log.
- لا تعلن جاهزية الإنتاج قبل اختبارات القبول والأمان والنسخ الاحتياطي.

## الأولوية
P0 حماية وفهم المشروع. P1 Demo متكامل. P2 تتبع المتطلبات والتوثيق. P3 تجهيز التطبيق الفعلي تدريجيًا.

## شروط اكتمال Demo
كل الصفحات الأساسية موجودة، الأزرار تعمل أو تشرح سبب تعطيلها، البحث والفلاتر فعالة، RTL وResponsive مضبوط، البيانات متسقة، تعليمات التشغيل موجودة ونتائج الاختبارات موثقة.
